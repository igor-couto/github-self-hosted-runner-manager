# Contributing to Runner Room

Thank you for your interest in contributing to **Runner Room**!

Open source thrives on collaboration, and every contribution matters. Whether you're fixing a bug, improving documentation, suggesting an idea, or implementing a new feature, your help is appreciated.

This guide explains how to get involved and contribute effectively. If you're new to open source, don't worry. Everyone starts somewhere, and questions are always welcome.

## Ways to Contribute

There are many ways to make Runner Room better, and not all of them involve writing code.

- **Report bugs:** Help identify issues and unexpected behavior.
- **Suggest features:** Share ideas that could improve the project.
- **Improve documentation:** Fix mistakes, clarify instructions, or add useful examples.
- **Contribute code:** Fix bugs, improve existing functionality, or implement new features.
- **Review pull requests:** Provide feedback, suggest improvements, and help maintain code quality.
- **Help others:** Answer questions and participate in discussions.

Even small contributions can make a meaningful difference.

## Getting Started

### 1. Find something to work on

Browse the repository's [Issues](../../issues) to find existing bugs, feature requests, or improvements.

Before starting a significant change, consider opening an issue to discuss your proposal. This helps ensure your work aligns with the project's goals and avoids duplicated effort.

For smaller changes, such as fixing typos or improving documentation, feel free to open a pull request directly.

### 2. Fork and clone the repository

Fork Runner Room to your GitHub account, then clone your fork locally.

```bash
git clone https://github.com/YOUR_USERNAME/runner-room.git
cd runner-room
```

Replace `YOUR_USERNAME` with your GitHub username.

### 3. Set up your development environment

Follow the setup instructions in the project's `README.md` to install the required dependencies and configure your local environment.

Before making changes, ensure you can build and run the project successfully.

### 4. Create a branch

Create a dedicated branch for your contribution.

```bash
git checkout -b fix/issue-description
```

Use a descriptive branch name that reflects your changes.

Some examples:

- `fix/incorrect-runner-status`
- `feat/add-runner-filtering`
- `docs/improve-setup-guide`
- `refactor/simplify-configuration`

## Development Guidelines

To keep the project maintainable and contributions easy to review, please follow these guidelines.

### Code quality

- Follow the existing coding conventions and project structure.
- Write clear, readable, and maintainable code.
- Keep changes focused on a single issue or improvement.
- Avoid introducing unnecessary dependencies or complexity.
- Prefer simple, well-understood solutions over clever abstractions.
- Add comments when they explain important decisions or non-obvious behavior.

### Testing

- Add or update tests when introducing or modifying functionality.
- Ensure existing tests continue to pass.
- Test relevant edge cases and error scenarios.
- Run applicable tests before submitting your pull request.

If a change cannot reasonably be covered by automated tests, explain how you verified it manually.

### Documentation

When your changes introduce new functionality, modify existing behavior, or affect configuration, update the relevant documentation accordingly.

Keep explanations clear and provide examples where useful.

### Commit messages

Write concise, descriptive commit messages that explain the purpose of your changes.

A good commit message should help someone understand what changed without having to inspect the entire diff.

## Submitting a Pull Request

Once your changes are ready:

1. Commit your changes to your feature branch.
2. Push your branch to your fork.
3. Open a pull request against the `main` branch of Runner Room.
4. Provide a clear description of your changes.
5. Reference any related issues when applicable.

## Review Process

Every pull request is reviewed with the goal of maintaining project quality while encouraging collaboration.

During review, you may receive feedback, questions, or suggestions for improvement. This is a normal part of the development process.

Please keep discussions constructive and focused on the code.

Not every proposal will necessarily be accepted, but every thoughtful contribution is appreciated. Sometimes a different approach may better fit the project's direction.

## Code of Conduct

Runner Room aims to provide a welcoming and respectful environment for everyone, regardless of experience or background.

Please:

- Be respectful and considerate.
- Welcome different perspectives and experience levels.
- Provide constructive feedback.
- Assume good intentions.
- Focus on ideas and solutions rather than individuals.

Harassment, discrimination, personal attacks, and disrespectful behavior are not tolerated.

## Questions and Support

If you have questions, need help getting started, or want to discuss an idea, feel free to [open an issue](../../issues).

There are no bad questions, and you don't need to have everything figured out before getting involved.

## Thank You!

Thank you for taking the time to contribute to Runner Room.

Whether your contribution is a single typo correction or a major new feature, you're helping make this project better for everyone.

**Happy coding, and welcome aboard!**
