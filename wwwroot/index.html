RUNNER LIFECYCLE

Runner management

Loading management settings…

Create runners / pool template

Registration settings may unregister and re-register a runner after draining it. This changes its GitHub runner ID and leaves it stopped. Labels and retry settings update in place. Created installations can switch between process and user-service modes; imported modes are preserved.

Import an existing installation

Import keeps the registration and files in place. Use the existing service mode. The dashboard account needs permission to control that service.

Managed runners

Drain waits for local and GitHub idle readings; busy or unknown readings block stopping. GitHub has no atomic pause API, so pause workflow producers for strict maintenance isolation. Removed managed folders are archived in .removed; imported folders are preserved.

Local runner pools

Save a pool template above, then set its desired count. Scaling down drains and unregisters members. Counts refer to installations on this server.

GitHub organization groups
Workflow runs

Attempts and results are refreshed from GitHub every 30 seconds. Reruns can take a moment to appear. Actions require a permitted repository and a token with Actions write access.
